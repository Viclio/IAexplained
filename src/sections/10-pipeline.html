10 — VUE D'ENSEMBLE

Le pipeline complet, bout à bout

Assemblons maintenant toutes les pièces. Voici ce qui se passe, précisément, quand vous cliquez sur « générer » dans l'interface d'un modèle de type Stable Diffusion.

En pseudocode

def generate_image(prompt, num_steps=30, cfg_scale=7.5, seed=None):
    # 1. Encoder le prompt (et un prompt vide pour CFG)
    text_emb = clip_text_encoder(prompt)
    empty_emb = clip_text_encoder("")

    # 2. Tirer un latent aléatoire
    torch.manual_seed(seed)
    z = torch.randn(1, 4, 64, 64)  # bruit gaussien

    # 3. Boucle de débruitage
    for t in scheduler.timesteps:  # de T=1000 vers t=0
        # Deux prédictions pour CFG
        noise_cond   = unet(z, t, text_emb)
        noise_uncond = unet(z, t, empty_emb)

        # Classifier-Free Guidance
        noise_pred = noise_uncond + cfg_scale * (noise_cond - noise_uncond)

        # Un pas de débruitage
        z = scheduler.step(noise_pred, t, z)

    # 4. Décoder le latent en image RGB
    image = vae_decoder(z)
    return image

Les samplers : différentes façons de calculer

Vous avez peut-être vu passer des noms comme Euler, DPM++ 2M Karras, DDIM, UniPC. Ce sont des samplers — les algorithmes qui décident comment appliquer, à chaque étape, la prédiction du bruit du U-Net pour obtenir le latent suivant. Ils diffèrent en :

  • Vitesse de convergence — certains produisent une image satisfaisante en 15 étapes, d'autres en demandent 50.
  • Déterminisme — DDIM est déterministe (l'image évolue peu le long du débruitage), d'autres injectent du bruit à chaque étape.
  • Style de rendu — Euler tend à donner un rendu « plus doux », DPM++ un rendu « plus contrasté ». Ces différences sont subtiles.

Sous le capot, tous résolvent numériquement la même équation différentielle stochastique — mais avec des méthodes différentes (Euler, Runge-Kutta d'ordre 2, méthodes multi-pas…).
